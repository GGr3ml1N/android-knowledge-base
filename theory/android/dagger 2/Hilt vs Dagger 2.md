**Hilt** — Google-обёртка над Dagger 2, которая генерирует boilerplate интеграции с Android-компонентами (Application, Activity, Fragment, ViewModel, Service...). Под капотом — тот же Dagger: граф, компоненты, кодогенерация. Hilt не «другой DI», а «Dagger + готовые стандартные компоненты + аннотации для Android».

### Что Hilt делает за вас
- Генерирует иерархию компонентов: `SingletonComponent -> ActivityRetainedComponent -> ActivityComponent -> FragmentComponent -> ViewComponent` со скоупами, привязанными к жизненному циклу Android-компонентов.
- `ViewModel` — через `@HiltViewModel` + `@Inject constructor` (без фабрик/мап с [[Multibindings]]).
- Входные точки — `@AndroidEntryPoint` вместо ручных компонентов и `inject(this)`.
- SavedStateHandle, WorkManager (@HiltWorker), Compose — готовые интеграции.

### Сравнение
| | Dagger 2 (vanilla) | Hilt |
| :--- | :--- | :--- |
| Компоненты | Пишете сами (AppComponent, ActivityComponent, сабкомпоненты) | Генерируются, фиксированная иерархия |
| ViewModel | Фабрика + Multibindings (см. [[Multibindings]]) | `@HiltViewModel` из коробки |
| Boilerplate | Много (компоненты, билдеры, фабрики) | Минимум |
| Гибкость | Полная: свои скоупы, кастомные компоненты, сложные графы | Ограничена иерархией Hilt (расширение возможно, но против grain'а) |
| Скорость компиляции | — | Часто быстрее (агрегированный компонент, меньше kapt-рабрики) |
| Тесты | Компоненты можно подменять | `@UninstallModules`, `TestInstallIn`, но менее гибко, чем ручной граф |

### Когда Dagger vanilla
- Сложные кастомные скоупы (например, скоуп на flow-навигацию, на пользовательскую сессию) вне стандартной иерархии.
- Библиотека/фреймворк, которому нужен свой граф независимо от приложения.
- Проект legacy с большой инвестицией в ручной Dagger (миграция стоит своих денег, но Hilt постепенно поглощает сценарии).

### Когда Hilt
- Стандартное приложение: Activity/Fragment/VM/Services — Hilt закрывает 95% кейсов с меньшим кодом.
- Быстрый старт нового проекта, маленькая команда — меньше DI-инфраструктуры в репозитории.
- Составная конструкция с Jetpack: Navigation Compose, WorkManager, Compose — первоклассная поддержка.

### На собесе
- «В чём разница?» — Hilt = Dagger + сгенерированная Android-иерархия компонентов; идеология та же (кодогенерация, compile-time safety, JSR-330).
- «Что выбрать?» — Hilt по умолчанию; Dagger vanilla — когда требуются нестандартные графы/скоупы или библиотечный DI.
- «Можно ли мигрировать с Dagger на Hilt?» — да, поэтапно: `@AndroidEntryPoint` + Hilt-компонент, совместимость через иерархию; обратно — тоже, но мало кто идёт.
