Безопасность мобильного приложения строится на одном факте: **приложение работает на устройстве, которое полностью контролирует пользователь** (или злоумышленник). APK можно декомпилировать (jadx), трафик перехватить (mitmproxy), память прочитать. Поэтому задача — не «невзламываемость», а **повышение стоимости атаки**.

### Основные угрозы
1. **Reverse engineering** — чтение логики, поиск секретов в коде (API-ключи, endpoint'ы).
2. **MITM** — перехват/подмена трафика между приложением и сервером.
3. **Утечка данных** — токены/пароли в SharedPreferences, логах, бэкапах.
4. **Root/эмулятор/отладка** — модифицированная ОС даёт злоумышленнику больше прав.
5. **Tampering** — модификация APK и повторная подпись (вредоносные клоны).

### Золотые правила
- **Никаких секретов в коде.** API-ключи в APK = публичная информация. Для клиент-серверной аутентификации используем стандартные OAuth2/OIDC-потоки (PKCE для публичных клиентов), где секрет живёт только на сервере.
- **Не доверяем клиенту.** Вся критичная валидация и бизнес-ограничения — на бэкенде.
- **Defense in depth** — много слоёв: обфускация + pinning + шифрование + root detection.
