### Контекст (важно для вакансии)
«Дистрибуция приложения без Google Play» — задача корпоративных/банковских приложений: Google Play может быть недоступен (Китай, корпоративные устройства, политика компании), а приложение должно обновляться и проверяться на целостность.

### Варианты дистрибуции
1. **Собственный сайт / корпоративный портал** — прямая загрузка APK. Требует: явное разрешение пользователя на установку (unknown sources), продвижение самим приложением.
2. **Alternative stores**: RuStore, Huawei AppGallery, Xiaomi GetApps, Amazon Appstore. Каждый — свои требования к подписи и ревью.
3. **MDM/EMM (Enterprise)**: Managed Google Play (через EMM), Samsung Knox, VMware Workspace ONE — пакеты разворачиваются администратором на корпоративные устройства (silent install).
4. **Sideload через adb** — для разработки и корпоративного развёртывания.

### Ключевая техническая часть: собственный апдейтер
Аналог in-app updates Google Play, но свой:
```kotlin
// 1. Запросить конфиг с сервера: минимальная/актуальная версия, url APK
// 2. Если versionCode < required -> принудительное обновление
// 3. Скачать APK (DownloadManager или через OkHttp в files dir)
// 4. Проверить целостность: SHA-256 файла == хэшу из конфига (подписан сервером)
// 5. Установить через PackageInstaller / Intent ACTION_INSTALL_PACKAGE (с FILE_PROVIDER)
val intent = Intent(Intent.ACTION_VIEW).apply {
    setDataAndType(apkUri, "application/vnd.android.package-archive")
    addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
}
startActivity(intent)
```

### Ограничения платформы
- **Unknown sources**: с Android 8+ разрешение даётся на конкретное приложение-установщик (`Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES`).
- **PackageInstaller API** для silent install доступен только с системными привилегиями/через MDM.
- Пользователь всегда видит системный диалог установки (кроме MDM).
- **Откат защиты**: `PackageManager` не даст поставить поверх APK с versionCode ниже (downgrade) — безопасность.

### Проверка целостности обновления
При скачивании APK из нестандартного источника критично:
1. Проверить SHA-256 файла против метаданных с доверенного сервера (HTTPS + pinning, см. [[SSL Pinning]]).
2. Проверить подпись: обновление должно быть подписано тем же сертификатом (Android сам это гарантирует при установке, но проверяем и в апдейтере до установки, чтобы не дергать пользователя зря).

### Безопасность канала обновлений (_supply chain_)
- Канал скачивания = самое уязвимое место. Обязательны: HTTPS + pinning, подписанные метаданные версии, блокировка отката (на бэкенде фиксируем минимальную версию).
- Дополнительно: Play Integrity при первом запуске, чтобы отличать официальную сборку от клона (см. [[Root and tamper detection]]).

### Стандартные вопросы
- «Как устроен ваш механизм обновлений?» — конфиг версий на сервере, принудительность, скачивание, проверка хэша/подписи, установка через PackageInstaller intent.
- «Как не дать установить поддельное обновление?» — подпись APK + серверная выдача хэша + SSL pinning + целостность самого приложения (Play Integrity).
