**Big O** — оценка роста ресурсов (времени/памяти) при увеличении входных данных `n`. Сравниваем алгоритмы при больших `n`, константы отбрасываем.

### Основные классы (по возрастанию)
```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n) < O(n!)
константная < логарифм < линейная < линейно-лог < квадратичная < экспоненциальная < факториал
```
| Сложность | n=10 | n=1000 | Пример |
| :--- | :--- | :--- | :--- |
| O(log n) | ~3 | ~10 | бинарный поиск |
| O(n) | 10 | 1000 | проход по списку |
| O(n log n) | ~30 | ~10k | хорошие сортировки |
| O(n²) | 100 | 1M | вложенные циклы, пузырёк |
| O(2^n) | 1024 | астрономия | перебор подмножеств |

### Правила вычисления
- Последовательные операции: берём максимум: `O(n) + O(log n) = O(n)`.
- Вложенность перемножается: два вложенных цикла по `n` → `O(n²)`.
- Константы отбрасываем: `O(2n) = O(n)`.
- Для разных входов — разные переменные: обход матрицы `O(n·m)`.

### Примеры оценки
```kotlin
// O(n)
fun sum(list: List<Int>): Int { var s = 0; for (x in list) s += x; return s }

// O(n²) — вложенные циклы
fun pairs(list: List<Int>): Int {
    var c = 0
    for (a in list) for (b in list) if (a + b == 0) c++
    return c
}

// O(n + m) — последовательные циклы
fun mergeLen(a: List<Int>, b: List<Int>) = a.size + b.size

// O(log n) — делим пополам
fun pow2Floor(n: Int): Int { var x = 1; while (x * 2 <= n) x *= 2; return x }
```

### Память (space complexity)
- O(1) — константная доп. память (in-place).
- O(n) — копия массива, рекурсия с глубиной n (стек вызовов!).

### Амортизированная сложность
Среднее время на операцию в длинной последовательности. ArrayList.add — O(1) амортизированно: иногда копирование O(n), но редко (редко / редко / редко). ArrayList.get — O(1), LinkedList.get — O(n) — поэтому в Android почти всегда ArrayList.

### Практические ориентиры для собеса
- `n ≤ 10` → O(n!) допустимо (перебор, permutations).
- `n ≤ 20-25` → O(2^n) (bitmask DP).
- `n ≤ 500` → O(n³) (Floyd).
- `n ≤ 10⁴` → O(n²) на грани.
- `n ≤ 10⁶` → O(n log n) или O(n).
- `n ≤ 10⁸` → O(n) / O(log n).

### Вопросы-ловушки
- Хеш-таблица: вставка/поиск O(1) **среднее**, O(n) худшее (коллизии).
- `n log n` у быстрых сортировок — почему log n: деление пополам (дерево рекурсии глубины log n) × линейная работа на уровне.
- Строковая конкатенация в цикле Java: `s += x` → O(n²) по суммарному копированию; StringBuilder → O(n).
