`docker` — управление контейнерами и образами

## СИНОПСИС

docker <КОМАНДА> [ОПЦИИ]

## ОПИСАНИЕ

`Docker` запускает процессы в изолированных контейнерах — «легких виртуальных машинах», собранных из образов. Основное применение в разработке: локальные экземпляры БД, брокеров сообщений и других сервисов без установки в систему.

## ПОНЯТИЯ

| Термин | Значение |
|---|---|
| Образ (image) | Неизменяемый шаблон: ОС + зависимости + приложение. Собирается слоями |
| Контейнер (container) | Запущенный экземпляр образа |
| Реестр (registry) | Хранилище образов; по умолчанию Docker Hub |
| Тег | Версия образа: `postgres:17` = образ postgres, тег 17; без тега — `latest` |
| Публикация портов | `-p <порт_хоста>:<порт_контейнера>` — проброс порта из контейнера наружу |
| Переменные окружения | `-e ИМЯ=значение` — настройка приложения внутри контейнера |
| Том (volume) | `-v <имя>:<путь>` — хранилище вне контейнера; данные переживают удаление контейнера |

## КОМАНДЫ

| Команда | Действие |
|---|---|
| `docker run [опции] <образ>` | Создать и запустить контейнер |
| `docker ps` | Список работающих контейнеров (`-a` — включая остановленные) |
| `docker stop <контейнер>` | Остановить (SIGTERM, затем SIGKILL) |
| `docker start <контейнер>` | Запустить существующий контейнер |
| `docker restart <контейнер>` | Перезапустить |
| `docker logs [-f] <контейнер>` | Логи контейнера; `-f` — следовать в реальном времени |
| `docker exec -it <контейнер> <команда>` | Выполнить команду внутри работающего контейнера (обычно шелл: `bash`/`sh` или `psql`) |
| `docker rm <контейнер>` | Удалить остановленный контейнер (`-f` — принудительно, работающий тоже) |
| `docker images` | Список образов локально |
| `docker rmi <образ>` | Удалить образ |
| `docker pull <образ>` | Скачать образ из реестра |
| `docker inspect <контейнер>` | JSON с полной информацией (IP, переменные, точки монтирования) |
| `docker stats` | Потребление CPU/памяти в реальном времени |

### Опции docker run

| Опция | Действие |
|---|---|
| `-d` | Фоновый режим (detached) |
| `--name <имя>` | Имя контейнера (иначе случайное) |
| `-e ИМЯ=значение` | Переменная окружения; повторяется для каждой |
| `-p хост:контейнер` | Публикация порта, напр. `-p 5432:5432` |
| `-v имя:путь` | Смонтировать том по пути внутри контейнера |
| `--rm` | Удалить контейнер автоматически после остановки |
| `-it` | Интерактивный режим с терминалом (для шелла) |

## ПРИМЕРЫ

```bash
# PostgreSQL для локальной разработки (имя fitness-postgres, БД fitness)
docker run --name fitness-postgres \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=fitness \
  -p 5432:5432 \
  -d postgres:17

# Проверить, что поднялся
docker ps

# Логи инициализации
docker logs fitness-postgres

# Список таблиц в БД изнутри контейнера
docker exec -it fitness-postgres psql -U postgres -d fitness -c '\dt'

# Интерактивная сессия psql
docker exec -it fitness-postgres psql -U postgres -d fitness

# Остановить / запустить снова
docker stop fitness-postgres
docker start fitness-postgres

# Полный сброс: удалить контейнер и поднять заново
docker rm -f fitness-postgres
docker run --name fitness-postgres ...  # та же команда

# Контейнер с автоматическим удалением (одноразовый)
docker run --rm -it postgres:17 psql --version
```

## ЗАМЕЧАНИЯ

- Имя контейнера уникально: повторный `docker run --name fitness-postgres` упадёт с «имя занято» → сначала `docker rm -f fitness-postgres`.
- Данные внутри контейнера не персистентны: `docker rm` удаляет и их. Для БД данные хранят в томе: `-v fitness-pgdata:/var/lib/postgresql/data` — тогда `docker rm` + новый контейнер с тем же томом = данные на месте.
- Образ не «устанавливается»: `docker run` сам скачает его при первом использовании.
- `docker exec` требует работающего контейнера; в остановленном процессов нет.
- На Linux команды docker требуют прав текущего пользователя (группа docker) или `sudo`.

## ОСТАЛЬНЫЕ КОМАНДЫ (обзор)

В мануале описано ядро для ежедневной разработки. Полный список команд Docker CLI — на docs.docker.com/reference/cli/docker/. Ниже — что ещё существует, одной строкой:

| Команда | Назначение |
|---|---|
| `docker build -t <имя> .` | Сборка образа из Dockerfile |
| `docker compose up -d` | Запуск стека из compose.yaml (приложение + БД разом) |
| `docker tag / push / login` | Публикация образов в реестр |
| `docker network create/ls` | Изолированные сети между контейнерами |
| `docker volume create/ls/inspect` | Управление томами данных |
| `docker port <контейнер>` | Показать проброшенные порты |
| `docker top <контейнер>` | Процессы внутри контейнера |
| `docker kill <контейнер>` | Немедленная остановка (SIGKILL) |
| `docker pause / unpause` | Заморозить/разморозить процессы контейнера |
| `docker cp <к>:<путь> <путь>` | Копирование файлов между контейнером и хостом |
| `docker save / load` | Экспорт/импорт образа в tar-архив |
| `docker history <образ>` | История слоёв образа |
| `docker events` | Поток событий демона |
| `docker system prune` | Очистка неиспользуемых образов/контейнеров/кэша (освобождает диск) |

Крупные темы (build, compose, registry, оркестрация) имеют собственные страницы: docker-build(1), docker-compose(1).
