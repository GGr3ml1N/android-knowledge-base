`git` — распределённая система контроля версий

## СИНОПСИС

git <КОМАНДА> [ОПЦИИ]

## ОПИСАНИЕ

Каждый коммит — снимок (snapshot) проекта со ссылкой на родителя; ветка — подвижный указатель на коммит; HEAD — указатель на текущую ветку. Хранилище объектов — в каталоге `.git`.

## ОБЛАСТИ ХРАНЕНИЯ — ключевая модель

```
рабочая директория          индекс (staging)          репозиторий (.git)
   (файлы)        --add-->   (что попадёт в коммит)  --commit-->  (история)
       ^                                                      |
       |________________________ checkout/reset ______________|
```

| Область | Что это | Попадает туда через |
|---|---|---|
| Рабочая директория | Файлы на диске, как есть | редактирование |
| Индекс (staging) | Подготовленные к коммиту изменения | `git add` |
| Репозиторий | Коммиты, ветки, теги | `git commit` |
| Удалённый (remote) | Копия на сервере (GitHub) | `git push` / `git pull` |

Из GUI индекс обычно невидим: кнопка Commit неявно делает add + commit. В CLI это два разных шага — и это даёт контроль, что именно войдёт в коммит.

## КОМАНДЫ И ОПЦИИ

### git status — состояние рабочей директории и индекса

| Опция | Действие |
|---|---|
| `-s, --short` | Компактный двухколоночный вывод: `M` (изменён), `A` (добавлен), `??` (не отслеживается) |
| `-b` | Показать текущую ветку и её состояние относительно remote |

### git add — подготовить изменения к коммиту

| Опция | Действие |
|---|---|
| `<файл>` | Добавить конкретный файл |
| `-A` | Все изменения во всём репозитории (включая удалённые файлы) |
| `.` | Все изменения от текущей директории |
| `-p` | Интерактивно: выбрать куски (hunk) изменений — что войдёт в коммит |
| `-n, --dry-run` | Показать, что было бы добавлено, не добавляя |
| `-f` | Добавить файл, игнорируемый по .gitignore |

### git rm — удаление файлов из git

Удаляет файл из рабочей директории И из индекса одним шагом. После этого нужен `git commit`, чтобы удаление попало в историю. Противопоставление `git add`: add регистрирует появление/изменение, rm — удаление.

| Опция | Действие |
|---|---|
| `<файл>` | Удалить файл с диска и из git |
| `--cached <файл>` | Убрать файл ТОЛЬКО из индекса: git перестаёт отслеживать его, на диске файл остаётся |
| `-r <директория>` | Рекурсивно удалить директорию |
| `-f, --force` | Принудительно, если у файла есть незакоммиченные изменения (без `-f` git откажётся, чтобы не потерять правки) |
| `-n, --dry-run` | Показать, что было бы удалено, не удаляя |
| `--ignore-unmatch` | Не падать с ошибкой, если файла нет (для скриптов) |
| `-q` | Тихий режим без вывода |

Ключевой сценарий — `--cached`: файл закоммитили случайно (секрет, `.idea/`, `build/`), а локально он нужен:

```bash
git rm --cached .idea/workspace.xml
echo ".idea/" >> .gitignore
git commit -m "Перестал отслеживать .idea"
```

Замечания:

- Просто удалить файл через `rm`/файловый менеджер тоже можно: git увидит его как deleted в `git status`, и `git add -A` зарегистрирует удаление. `git rm` делает то же самое одним шагом.
- После удаления из истории файл можно вернуть: `git restore <файл>` (пока не закоммичено) или `git checkout <коммит> -- <файл>`.
- `git rm --cached` не удаляет файл из прошлых коммитов — история сохраняется; секреты из истории вычищают отдельно (filter-repo, BFG).

### git commit — создать коммит из индекса

| Опция | Действие |
|---|---|
| `-m "текст"` | Сообщение без открытия редактора; повтор `-m` даёт абзацы |
| `-a` | Закоммитить все изменённые ОТСЛЕЖИВАЕМЫЕ файлы без add (новые файлы не трогает) |
| `--amend` | Дополнить последний коммит (ещё не отправленный): добавить изменения и/или изменить сообщение |
| `--amend --no-edit` | Дополнить последний коммит, оставив сообщение прежним |
| `--no-verify` | Пропустить git hooks (не рекомендуется) |

### git log — история коммитов

| Опция | Действие |
|---|---|
| `--oneline` | Одна строка на коммит: хеш + сообщение |
| `-n N` | Последние N коммитов |
| `--graph` | ASCII-дерево ветвлений и слияний |
| `--all` | История всех веток, а не текущей |
| `--decorate` | Подписи веток и тегов у коммитов (часто включено по умолчанию) |
| `--since="2 days ago"`, `--until=...` | Фильтр по дате |
| `--author="имя"` | Фильтр по автору |
| `-p` | Показать diff каждого коммита |
| `--stat` | Статистика изменений (файлы, +/- строк) |
| `-- <файл>` | История конкретного файла |
| `--follow` | Продолжать историю файла через переименования |

### git diff — разница между областями хранения

| Форма | Что сравнивает |
|---|---|
| `git diff` | рабочая директория vs индекс |
| `git diff --cached` (или `--staged`) | индекс vs HEAD |
| `git diff HEAD` | рабочая директория vs HEAD |
| `git diff <ветка>` | рабочая директория vs ветка |
| `git diff <коммит1> <коммит2>` | коммит1 vs коммит2 |

| Опция | Действие |
|---|---|
| `-- <файл>` | Только указанный файл |
| `--stat` | Статистика вместо полного diff |

### git switch — переключение веток

| Опция | Действие |
|---|---|
| `<ветка>` | Переключиться на существующую |
| `-c <новая>` | Создать ветку и переключиться |
| `-` | Предыдущая ветка (туда-обратно) |

### git branch — управление ветками

| Опция | Действие |
|---|---|
| (без опций) | Список локальных веток |
| `-a` | Включая удалённые |
| `-vv` | С отслеживанием: какая ветка за каким remote следует и насколько разошлась |
| `-d <ветка>` | Удалить слитую ветку (безопасно) |
| `-D <ветка>` | Удалить принудительно, даже неслитую |
| `-m <старое> <новое>` | Переименовать |

### git merge — слияние веток

| Опция | Действие |
|---|---|
| `--no-ff` | Создать коммит слияния даже при возможности fast-forward |
| `--squash` | Влить изменения, но не создавать коммит слияния — одним коммитом |
| `--abort` | Отменить слияние, остановленное из-за конфликта |

### git restore — откат изменений

| Опция | Действие |
|---|---|
| `<файл>` | Вернуть файл в рабочей директории к состоянию индекса (незакоммиченные правки теряются) |
| `--staged <файл>` | Убрать файл из индекса (правки остаются в рабочей директории) |
| `--source <коммит>` | Взять версию файла из указанного коммита |
| `.` | Применить ко всем файлам |

### git reset — перемещение указателей

| Опция | Что происходит |
|---|---|
| `--soft <точка>` | Сдвинуть HEAD; индекс и рабочая директория не трогаются |
| `--mixed <точка>` (по умолчанию) | Сдвинуть HEAD и сбросить индекс; рабочая директория не трогается |
| `--hard <точка>` | Сдвинуть HEAD, сбросить индекс И рабочую директорию — изменения теряются безвозвратно |

Точка задаётся как `HEAD~N` (N коммитов назад) или хеш коммита.

### git revert — отмена опубликованного коммита

| Опция | Действие |
|---|---|
| `<коммит>` | Создать новый коммит, обратный указанному |
| `--no-edit` | Сообщение по умолчанию без редактора |
| `-n, --no-commit` | Применить отмену в рабочую директорию, не коммитя |

### git stash — временное укрытие изменений

| Команда | Действие |
|---|---|
| `stash` (или `push`) | Спрятать незакоммиченные изменения в стек |
| `push -u` | Включая неотслеживаемые файлы (?? в status) |
| `push -m "имя"` | Спрятать с подписью |
| `pop` | Вернуть последнее и удалить из стека |
| `apply` | Вернуть последнее, оставить в стеке |
| `list` | Список спрятанного |
| `show -p` | Показать diff последнего элемента |
| `drop` | Удалить последнее из стека |

### git pull / git push — обмен с remote

| Опция (pull) | Действие |
|---|---|
| `--rebase` | Накатить свои коммиты поверх свежего remote (линейная история) |
| `--ff-only` | Обновиться только fast-forward, иначе ошибка (защита от случайных merge-коммитов) |

| Опция (push) | Действие |
|---|---|
| `-u, --set-upstream` | Запушить ветку и запомнить связь с удалённой (дальше просто `git push`) |
| `--force-with-lease` | Переписать удалённую историю, но только если никто не запушил новое (безопасный force) |
| `--tags` | Запушить теги |
| `--delete <ветка>` | Удалить удалённую ветку |

### git tag — метки на коммитах

| Опция | Действие |
|---|---|
| `<имя>` | Лёгкий тег (просто указатель) |
| `-a <имя> -m "сообщение"` | Аннотированный тег (объект с автором и сообщением — для релизов) |
| `-d <имя>` | Удалить тег |
| (push) `git push origin <имя>` / `--tags` | Отправить тег(и) на сервер |

### git show / git blame — просмотр и расследование

| Опция | Действие |
|---|---|
| `show --stat <коммит>` | Коммит со статистикой файлов |
| `show --name-only <коммит>` | Коммит со списком файлов без diff |
| `show <коммит>:<файл>` | Содержимое файла в указанном коммите |
| `blame -L 10,25 <файл>` | Кто менял строки 10–25 |
| `blame -w <файл>` | Игнорировать переносы строк |

### git reflog — журнал HEAD

Без опций: список всех перемещений HEAD (коммиты, переключения, reset). Спасение при «удалил ветку» / «откатился не туда»: найти хеш, затем `git reset --hard <хеш>`.

## GUI → CLI: быстрый маппинг

| Действие в GUI | Команда |
|---|---|
| Нажал Commit (с выбранными файлами) | `git add <файлы> && git commit -m "..."` |
| Discard changes у файла | `git restore <файл>` |
| Unstage / убрать из коммита | `git restore --staged <файл>` |
| Amend last commit | `git commit --amend` |
| Pull | `git pull` |
| Push | `git push` |
| Создать ветку | `git switch -c имя` |
| Слить ветку | `git merge имя` |

## ПРИМЕРЫ

```bash
# Типичный рабочий цикл
git status
git add -A
git commit -m "Добавил валидацию CreateWorkoutRequest"
git pull
git push

# Коммит части изменений (интерактивно)
git add -p src/main/kotlin/...
git commit -m "Только валидация, без остального"

# Работа в ветке фичи
git switch -c feature/workouts-api
# ... правки, коммиты ...
git switch main
git merge feature/workouts-api
git push

# Удалить последний локальный коммит, изменения сохранить
git reset --soft HEAD~1

# Отменить уже запушенный коммит
git revert HEAD
git push

# Всё сломалось — найти, где HEAD был час назад
git reflog
```

## ЗАМЕЧАНИЯ

- `.gitignore` в корне — список того, что git игнорирует (`build/`, `.idea/`, `*.log`). Шаблоны для языков: github.com/github/gitignore.
- Коммиты — маленькие и частые: один коммит = одно осмысленное изменение.
- Опубликованную (запушенную) историю не переписывают: вместо `reset --hard` + force push — `git revert`. Если переписывание необходимо — только `push --force-with-lease`.
- `git pull` по умолчанию создаёт merge-коммиты; `git pull --rebase` делает историю линейной — многие команды работают так.
- Восстановить «удалённое навсегда» почти невозможно только если не прошло 90 дней: `git reflog` + `git reset --hard <хеш>`.
- Переносы строк: `core.autocrlf` (Windows), `.gitattributes`.
