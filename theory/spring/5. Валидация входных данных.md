# Урок 5. Валидация входных данных

## Два типа «неправильных данных»

| Тип | Пример | Где возникает | Исключение | Статус по умолчанию |
|---|---|---|---|---|
| Синтаксический | `{"name": 123}`, битый JSON | Десериализация Jackson | `HttpMessageNotReadableException` | 400 |
| Семантический | `{"name": ""}`, `date = -5` | Проверка правил | `MethodArgumentNotValidException` | 400 |

```json
// синтаксис: name не парсится в String
{"name": 123}

// семантика: парсится нормально, но нарушает правила
{"name": "", "date": -5}
```

- Синтаксические ошибки ловит сам Spring (Jackson не смог собрать объект).
- Семантические — Bean Validation: ограничения на полях DTO + @Valid на параметре контроллера.

## Bean Validation

- Спецификация `jakarta.validation`; в проект входит через `spring-boot-starter-validation`.
- Ограничения — аннотации на полях DTO запроса:

| Аннотация | Проверка |
|---|---|
| `@NotNull` | Значение не null |
| `@NotBlank` | Строка не null, не пустая и не из пробелов |
| `@Size(min, max)` | Длина строки/коллекции в диапазоне |
| `@Positive` / `@Negative` | Число > 0 / < 0 |
| `@Min(n)` / `@Max(n)` | Число в границах |
| `@Pattern(regexp)` | Строка по регулярному выражению |

- У каждой аннотации есть `message = "..."` — текст нарушения, попадёт в ответ.

Пример DTO с ограничениями:

```kotlin
data class CreateWorkoutRequest(
    @field:NotBlank(message = "name must not be blank")
    @field:Size(max = 100, message = "name must be at most 100 characters")
    val name: String,

    @field:Positive(message = "date must be a positive epoch millis")
    val date: Long
)
```

## Kotlin: куда целится аннотация

- Аннотация на параметре конструктора data class по умолчанию применяется к `param` — валидатор его не видит.

```kotlin
// так аннотация попадёт на параметр конструктора и валидация молча не сработает:
@NotBlank val name: String

// правильно — на поле (use-site target @field:):
@field:NotBlank val name: String
```

- Флаг компилятора `-Xannotation-default-target=param-property` (есть в шаблоне Initializr) дублирует аннотации на property, но явный `@field:` читается понятнее и не зависит от флага.

## Запуск валидации

- `@Valid` (jakarta: `jakarta.validation.Valid`) на параметре `@RequestBody`. Валидация выполняется до входа в метод контроллера; при нарушении — `MethodArgumentNotValidException`.

```kotlin
@PostMapping
fun addWorkout(@Valid @RequestBody workout: CreateWorkoutRequest): WorkoutDto {
    // сюда попадает только прошедшая проверку DTO
}
```

## Кастомные хендлеры

- На семантические нарушения — хендлер с разбором field errors:

```kotlin
@ExceptionHandler(MethodArgumentNotValidException::class)
fun handleValidation(ex: MethodArgumentNotValidException): ProblemDetail {
    val details = ex.bindingResult.fieldErrors
        .joinToString("; ") { "${it.field}: ${it.defaultMessage}" }
    return ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, details)
}
```

- На синтаксические — общий текст без деталей (внутренности маппинга клиенту не нужны):

```kotlin
@ExceptionHandler(HttpMessageNotReadableException::class)
fun handleUnreadableBody(ex: HttpMessageNotReadableException): ProblemDetail =
    ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, "Malformed JSON or wrong field types")
```

- Пример ответа на `{"name": "", "date": -5}`:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "name: name must not be blank; date: date must be a positive epoch millis"
}
```

- Позиция Spring — 400 для обоих случаев; 422 Unprocessable Entity как ответ на семантические ошибки — допустимая альтернатива, важно единообразие внутри API.

## Где валидировать

- На границе — на DTO запроса. Чем раньше отсечён мусор, тем чище сервис и БД. Сервис валидировать повторно не нужно (контракт: до сервиса доходят только прошедшие проверку данные).

## Соглашения API: пустая коллекция

- GET коллекции: пустой результат → 200 OK и `[]`. 404 — только для одиночного ресурса по id: коллекция не «отсутствует», она просто пуста.
- Проверка `isEmpty()` перед `firstOrNull` избыточна: `firstOrNull` на пустом списке сам возвращает null.
