## Бин
**Бин** — объект, жизненным циклом которого управляет Spring: создание, хранение в контейнере, внедрение в другие объекты, уничтожение. Класс становится бином после пометки аннотацией-стереотипом.

## Component scan
`@SpringBootApplication` (Spring: `org.springframework.boot.autoconfigure.SpringBootApplication`) — составная аннотация:

| Составная часть | Назначение |
|---|---|
| `@Configuration` | Класс может содержать настройки и объявления бинов |
| `@EnableAutoConfiguration` | Автоматическая конфигурация на основе зависимостей в classpath |
| `@ComponentScan` | Сканирование пакета, в котором лежит класс с `@SpringBootApplication`, и всех вложенных пакетов в поисках классов со стереотипными аннотациями |                                                                   

Следствие: классы вне дерева пакетов точки входа (`com.ggr3ml1n.backend` и ниже) не регистрируются — component scan их не видит.

## Стереотипные аннотации
Пакет: `org.springframework.stereotype` (кроме `@RestController`)

| Аннотация | Роль | Ближайшая аналогия в Android |
|---|---|---|
| `@Component` | Общий случай, конкретная роль не задана | — |
| `@Service` | Бизнес-логика | UseCase / ViewModel |
| `@Repository` | Доступ к данным | DAO из Room |
| `@RestController` | HTTP-слой | — (приём запросов вместо отправки) |

Различия технически минимальны, семантические — метка архитектурного слоя.

## Внедрение зависимостей (DI)

Единственный используемый способ — **конструкторная инъекция**: зависимость объявляется параметром конструктора, Spring находит нужный бин в контейнере и передаёт его. В Kotlin с единственным конструктором `@Autowired` не требуется.

Преимущества конструктора перед инъекцией в поле:
- неизменяемость объекта после создания;
- зависимости явно видны в сигнатуре класса;
- тестируемость без поднятия контейнера.

## Скоупы
По умолчанию бин — **singleton**: один экземпляр на всё приложение (аналог `@Singleton` в Dagger/Hilt). Бины не хранят состояние —
состояние живёт в БД. Альтернатива: `@Scope("prototype")` — новый экземпляр при каждом запросе из контейнера.

## Auto-configuration
Spring Boot настраивает компоненты по содержимому classpath: наличие `spring-boot-starter-web` → встроенный Tomcat на порту 8080 + Jackson для JSON; наличие `spring-boot-starter-data-jpa` без параметров подключения → падение при старте с ошибкой конфигурации `DataSource`. Зависимость, присутствующая в classpath, но не настроенная — источник ошибок запуска.

## CommandLineRunner — демонстрация IoC
Интерфейс Spring: `org.springframework.boot.CommandLineRunner`, метод `run(vararg args: String?)`. Spring Boot после старта контекста сам находит все бины, реализующие этот интерфейс, и вызывает у каждого `run()`. Пользовательский  код метод не вызывает — пример инверсии управления: фреймворк вызывает код приложения.
