## Обработка HTTP-запроса в Spring MVC
1. При старте приложения со стартером spring-boot-starter-web поднимается встроенный Tomcat (порт по умолчанию — 8080).
2. Все HTTP-запросы попадают в DispatcherServlet (Spring: `org.springframework.web.servlet.DispatcherServlet`) — front controller, единая точка входа. Создаётся автоматически, вручную не объявляется.
3. `DispatcherServlet` ищет среди бинов с аннотацией `@RestController` метод, чей маппинг (URL + HTTP-метод) совпал с запросом.
4. Аргументы метода собираются из частей запроса с помощью аннотаций параметров.
5. Возвращаемое значение сериализуется в JSON библиотекой Jackson (входит в состав стартера) и отправляется клиенту. Статус по умолчанию — 200 OK.

## @RestController
- Пакет: `org.springframework.web.bind.annotation.RestController`.
 - Составная аннотация: `@Controller + @ResponseBody`.
-  `@ResponseBody` — признак того, что возвращаемое значение метода является телом ответа, а не именем представления (последнее относится к серверному рендерингу страниц, в REST API не используется).
- Класс с этой аннотацией при component scan регистрируется как бин и становится доступен `DispatcherServlet`.

   ## Аннотации маппинга и параметров
   Пакет: `org.springframework.web.bind.annotation`
   
| Аннотация                                              | Назначение                                   | Пример                   |
|:------------------------------------------------------ |:-------------------------------------------- |:------------------------ |
| @GetMapping, @PostMapping, @PutMapping, @DeleteMapping | Привязка метода к URL и HTTP-методу          | @GetMapping("/workouts") |
| @PathVariable                                          | Подстановка части пути в параметр            | /workouts/{id} → id      |
| @RequestParam                                          | Query-параметр                               | /workouts?page=2 → page  |
| @RequestBody                                           | Десериализация тела запроса из JSON в объект | POST с JSON-телом        |

Маппинг объявляется на методе. При объявлении на классе задаёт общий префикс URL для всех его методов.
   
## DTO (Data Transfer Object)
- data class, описывающий контракт API: формат входящих и исходящих данных.
- Отделяется от доменной модели и модели БД. Причины: схема БД и контракт API эволюционируют независимо; сущности персистентности несут аннотации хранения, DTO остаются чистыми данными; одна сущность может иметь разные представления  для разных эндпоинтов.
- Правило слоя: контроллер работает только с DTO.                               

## Статус-коды ответов
- Успешный ответ по умолчанию — 200 OK.                                                                                                                                                                                                   
- Точное управление статусами (201 Created, 404 Not Found и т.д.) рассматривается в уроке об обработке ошибок (ResponseEntity, @ControllerAdvice).

## Маппинг на уровне класса
- `@RequestMapping("/workouts")` (Spring: `org.springframework.web.bind.annotation.RequestMapping`) на классе задаёт общий префикс URL для всех эндпоинтов контроллера.
- Итоговый путь = префикс класса + путь метода.
- `@GetMapping` без аргументов → путь метода пустой → эндпоинт совпадает с префиксом класса.
- `@GetMapping`, `@PostMapping` и др. — сокращения `@RequestMapping` с фиксированным HTTP-методом: `@GetMapping("/x")` ≡ `@RequestMapping(path = ["/x"], method = [RequestMethod.GET])`. Поэтому на уровне класса используется общий `@RequestMapping`, а на методах — конкретные аннотации: HTTP-метод — часть контрата эндпоинта.
- У `@RestController` нет атрибута URL: строковый параметр `value` — имя бина (наследуется от `@Component`). Запись `@RestController("/workouts")` переименовывает бин, маппинг не создаёт.
