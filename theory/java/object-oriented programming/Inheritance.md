**Наследование** — механизм создания класса на основе другого: подкласс (subclass) наследует поля и методы суперкласса (superclass), может расширять и переопределять их. `extends` для классов, `implements` для интерфейсов.

```java
public class Animal {
    protected String name;
    public void speak() { System.out.println("..."); }
}

public class Dog extends Animal {
    @Override public void speak() { System.out.println("Woof"); }
}
```

### Правила и нюансы
- Java — **одиночное наследование классов** (нет diamond problem), множественное — для интерфейсов.
- `super.method()` — вызов реализации родителя; `super()` — конструктор родителя (всегда первой строкой конструктора, неявно).
- Конструкторы не наследуются.
- `private` члены не наследуются (доступны только через public/protected API родителя).
- `final class` запрещает наследование; `final method` — переопределение.

### Модификаторы при наследовании
- Переопределённый метод не может сужать видимость (public → protected запрещено).
- Нельзя переопределять `static` методы (это hiding, не overriding).
- Ковариантность возврата: переопределение может возвращать подтип (`Animal getPet()` → `Dog getPet()`).

### Порядок инициализации (классика собеса)
При `new Dog()`:
1. Статические блоки родителя → статические блоки потомка (один раз на класс).
2. Поля родителя + конструктор родителя.
3. Поля потомка + конструктор потомка.
```java
class A { A() { System.out.println("A"); } }
class B extends A { B() { System.out.println("B"); } }
new B(); // "A" затем "B"
```
Ловушка: виртуальный вызов из конструктора — вызовет метод потомка до инициализации его полей (NPE-риск).

### Переопределение (overriding) vs перегрузка (overloading)
| Overriding | Overloading |
| :--- | :--- |
| Подкласс, та же сигнатура, рантайм-полиморфизм | Тот же класс, другие параметры, компилй-тайм |
| `@Override` | Выбор метода на этапе компиляции |

### Сравнение с Kotlin
- Kotlin классы `final` по умолчанию — наследование только при явном `open`.
- `override` обязателен, `open` для переопределяемых членов.
- Наследование через `:` : `class Dog : Animal()`.

### Проблемы наследования (для Senior-разговора)
- **Хрупкость базового класса**: изменение суперкласса ломает подклассы (fragile base class).
- **Нарушение инкапсуляции**: подкласс зависит от деталей реализации родителя.
- Поэтому правило: **предпочитайте композицию наследованию** («Effective Java», Joshua Bloch). Наследование оправдано для «is-a» с честной иерархией (framework-классы, sealed-иерархии в Kotlin), композиция — для «has-a» и переиспользования логики.
